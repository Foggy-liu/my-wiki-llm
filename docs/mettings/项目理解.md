# 文物IP内容自动化生产链 - 项目理解

> 本文档旨在帮助理解从 Demo 到工程化项目的演进路径，以及各模块如何衔接

---

## 一、整体架构对比

### Demo 版本（当前实现）

```
用户输入 → intent_parser → Wiki检索 → 脚本生成 → Prompt生成 → 输出
              ↓              ↓           ↓           ↓
          简单规则匹配    遍历文件    Mock生成    模板填充
```

**特点**：
- 轻量级实现，单人能完成
- Wiki 用文件系统存储
- 检索是简单关键词匹配
- 生成层和对接层是 Mock 实现

---

### 工程化版本（生产环境）

```
用户输入 → 意图识别服务 → RAG引擎 → LLM服务 → 脚本校验 → Prompt生成 → 输出
              ↓             ↓          ↓         ↓           ↓
          AI模型分类    向量检索    GPT-4    事实核查    多平台适配
```

**特点**：
- 服务化架构，支持多用户
- Wiki 用向量数据库 + 文件系统
- 检索是向量检索 + 关键词混合
- 完整 LLM 生成能力

---

## 二、各层详细对比

### 1. 资料层对比

| 维度 | Demo | 工程化 |
|------|------|--------|
| **存储** | 文件系统（Markdown） | 文件系统 + 向量数据库 |
| **检索方式** | 关键词匹配 | 向量检索（FAISS/Milvus）+ BM25 |
| **Embedding** | Mock随机向量 | 真实模型（text-embedding-3-small） |
| **知识管理** | 手动创建页面 | Ingest自动化流程 |
| **规模** | ~100页面 | 百万级向量 |
| **一致性** | 无版本管理 | lifecycle管理（置信度、状态） |

### 2. 生成层对比

| 维度 | Demo | 工程化 |
|------|------|--------|
| **脚本生成** | Mock模板 | LLM API调用 |
| **事实核查** | 无 | FactConstraintEngine |
| **引用溯源** | 简化 | 完整引用标注 |
| **质量评估** | 无 | 独立评估模块 |

### 3. 对接层对比

| 维度 | Demo | 工程化 |
|------|------|--------|
| **Prompt模板** | 硬编码 | 模板引擎（Jinja2） |
| **平台支持** | Sora单一 | Sora/Runway/Kling多平台 |
| **参数调优** | 固定 | 可配置 |

## 三、Demo 实现详解

### 3.1 目录结构

```
artifact_chain/
├── wiki/                        # Wiki知识库
│   ├── entities/                # 实体（文物）
│   │   ├── 青铜面具.md
│   │   └── 三星堆遗址.md
│   └── concepts/                # 概念（方法论）
│       ├── 悬疑叙事技巧.md
│       └── 短视频脚本结构.md
├── src/
│   ├── intent_parser.py         # 意图解析（规则匹配）
│   ├── wiki_kb.py               # Wiki操作（文件读写）
│   ├── retriever.py             # 检索（关键词匹配）
│   ├── script_gen.py            # 脚本生成（Mock）
│   └── prompt_gen.py            # Prompt生成（Mock）
├── main.py                      # 主入口
└── requirements.txt             # 依赖
```

### 3.2 数据流

```
用户输入: "以青铜面具为主角，写一个60秒悬疑风短视频脚本。"

    ↓
intent_parser.parse()
    ↓
UserIntent:
  - artifact: "青铜面具"
  - style: "悬疑"
  - duration: 60
  - intent_type: "脚本"

    ↓
retriever.retrieve(intent)
    ↓
[RetrievedEntry("青铜面具", ...), RetrievedEntry("悬疑叙事技巧", ...)]

    ↓
script_gen.generate()
    ↓
ScriptResult:
  - script: "【悬疑风格短视频脚本】..."
  - citations: ["[[wiki/entities/青铜面具.md]]"]

    ↓
prompt_gen.generate()
    ↓
PromptResult:
  - prompt: "Cinematic footage, mysterious atmosphere..."
  - platform: "sora"
```

### 3.3 Demo 的局限性

| 局限 | 说明 |
|------|------|
| **检索不准** | 关键词匹配无法理解语义 |
| **生成质量差** | Mock内容无法真正利用知识 |
| **无事实约束** | 无法验证生成内容是否基于资料 |
| **难以扩展** | 文件遍历无法应对海量数据 |

### 4.2 核心模块详解

#### 4.2.1 Ingest Service（消化服务）

**职责**：将原始资料消化成 Wiki 页面

**流程**：
```
raw/新资料 → 读取 → 提取引用/概念 → 创建/更新Wiki页面 → 维护交叉引用 → 更新index → 记录log
```

**关键能力**：
- 自动识别实体和概念
- 维护 [[wikilinks]] 交叉引用
- 冲突检测与标注
- lifecycle 置信度更新

#### 4.2.2 Query Service（查询服务）

**职责**：回答用户问题

**流程**：
```
用户问题 → 读取index → 定位相关页面 → 深读页面 → 综合回答 → 更新lifecycle → 记录log
```

**关键能力**：
- 优先高置信度页面
- 标注 stale 页面
- 询问是否归档有价值答案

#### 4.2.3 RAG 引擎（检索增强生成）

**职责**：为生成层提供上下文

**流程**：
```
用户问题 → Embedding → 向量检索 → BM25检索 → 混合 → 重排序 → Top-K → 上下文
```

**关键组件**：

| 组件 | Demo | 工程化 |
|------|------|--------|
| **Embedding** | Mock | text-embedding-3-small |
| **向量存储** | 无 | FAISS/Milvus |
| **关键词检索** | 字符串匹配 | BM25 |
| **重排序** | 无 | Cross-encoder rerank |

#### 4.2.4 Fact Checker（事实核查）

**职责**：确保生成内容基于资料

**流程**：
```
生成内容 → 声明提取 → 资料验证 → 冲突检测 → 违规标注 → 置信度报告
```

**关键能力**：
- NER 提取事实声明
- 资料库验证
- 矛盾检测与标注

## 六、工程化项目的模块衔接

### 6.1 完整数据流

```
┌─────────────────────────────────────────────────────────────────────────┐
│                           用户请求                                      │
│                    "以青铜面具为主角，写悬疑脚本"                         │
└─────────────────────────────────────────────────────────────────────────┘
                                    ↓
                                    ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                        Intent Service（意图识别）                          │
│  - 调用 LLM 识别用户意图                                                  │
│  - 提取：artifact, style, intent_type, duration                          │
│  输出：UserIntent 结构                                                    │
└─────────────────────────────────────────────────────────────────────────┘
                                    ↓
                                    ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                        Query Service（查询服务）                          │
│  - 读取 index.md 定位相关页面                                            │
│  - 读取 Wiki 页面获取知识                                                │
│  输出：Context（包含史实+方法论）                                         │
└─────────────────────────────────────────────────────────────────────────┘
                                    ↓
                                    ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                        RAG Engine（检索引擎）                             │
│  - Hybrid Retriever：向量 + BM25                                        │
│  - Reranker：重排序                                                      │
│  - 返回 Top-K 相关知识                                                   │
│  输出：RetrievedContext                                                  │
└─────────────────────────────────────────────────────────────────────────┘
                                    ↓
                                    ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                      Script Generator（脚本生成）                           │
│  - 构建 RAG Prompt（意图 + 上下文）                                      │
│  - 调用 LLM 生成脚本                                                     │
│  - 提取引用信息                                                          │
│  输出：ScriptResult                                                      │
└─────────────────────────────────────────────────────────────────────────┘
                                    ↓
                                    ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                      Fact Checker（事实核查）                              │
│  - 提取脚本中的声明                                                      │
│  - 与 Wiki 资料对比验证                                                  │
│  - 标注冲突和置信度                                                      │
│  输出：FactCheckReport                                                   │
└─────────────────────────────────────────────────────────────────────────┘
                                    ↓
                                    ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                      Prompt Generator（Prompt生成）                        │
│  - 解析脚本结构（场景、镜头、画面）                                       │
│  - 填充 Prompt 模板                                                      │
│  - 多平台适配                                                            │
│  输出：VideoPrompt                                                       │
└─────────────────────────────────────────────────────────────────────────┘
                                    ↓
                                    ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                           最终输出                                       │
│                    AI视频生成Prompt（可直接使用）                          │
└─────────────────────────────────────────────────────────────────────────┘
```

### 6.2 模块间接口定义

#### 6.2.1 Intent Service → Query Service

```python
@dataclass
class UserIntent:
    raw_input: str
    artifact: Optional[str]      # 文物/素材
    style: Optional[str]         # 风格
    intent_type: Optional[str]   # 脚本/视频/文案
    duration: Optional[int]      # 时长（秒）
    confidence: float = 1.0      # 意图识别置信度
```

#### 6.2.2 Query Service → RAG Engine

```python
@dataclass
class QueryRequest:
    intent: UserIntent
    knowledge_types: List[str]   # ["entities", "concepts"]
    top_k: int = 5
```

#### 6.2.3 RAG Engine → Script Generator

```python
@dataclass
class RetrievedContext:
    entries: List[RetrievedEntry]  # 检索到的知识
    citations: List[Citation]      # 引用信息
    confidence: float              # 综合置信度
```

#### 6.2.4 Script Generator → Fact Checker

```python
@dataclass
class ScriptResult:
    script: str
    structure: ScriptStructure    # 场景分解
    citations: List[Citation]
    raw_prompt: str               # 原始LLM prompt
```

#### 6.2.5 Fact Checker → Prompt Generator

```python
@dataclass
class FactCheckReport:
    is_valid: bool
    violations: List[Violation]
    confidence: float
    warnings: List[str]           # 潜在问题警告
```

#### 6.2.6 Prompt Generator → 最终输出

```python
@dataclass
class VideoPrompt:
    prompt: str
    platform: str                # sora/runway/kling
    scenes: List[Scene]
    metadata: Dict               # 额外元数据
```

## 八、面试时如何阐述

### 8.1 强调工程思维

> "我理解 Demo 和生产环境的差距。Demo 用文件系统 + 关键词匹配可以快速验证思路，但工程化需要考虑：海量数据的检索效率、多用户并发、知识持续积累、生成质量保障等。"

### 8.2 展示扩展路径

> "如果数据量从 100 条扩展到 10 万条，我会：
> 1. 用 FAISS 替换文件遍历，实现毫秒级向量检索
> 2. 用 qmd 工具增强搜索能力，支持混合检索
> 3. 实现 Ingest 自动化流程，让知识持续积累
> 4. 接入 Lifecycle 管理，追踪知识健康度"

### 8.3 解释模块衔接

> "资料层输出的结构化上下文，直接决定了生成层的输入质量。我设计了清晰的接口（UserIntent、RetrievedContext、ScriptResult），让每一层的输入输出都明确可控，便于独立测试和迭代。"

## 九、附录：技术选型参考

| 场景 | 推荐方案 | 原因 |
|------|---------|------|
| **向量数据库** | FAISS（轻量）/ Milvus（生产） | FAISS 本地无需运维，Milvus 支持分布式 |
| **Embedding** | text-embedding-3-small | 性价比高，OpenAI 官方 |
| **LLM** | GPT-4o-mini（初期）/ 开源（成本敏感） | 成本与质量平衡 |
| **搜索工具** | qmd | 轻量、支持混合搜索、有 MCP 接口 |
| **知识图谱** | 可选（数据量大时） | Neo4j 存储实体关系 |

## 十、总结

| 阶段 | 重点 | 交付 |
|------|------|------|
| **Demo** | 跑通核心流程 | 架构图 + 资料层实现 |
| **Phase 1** | 增强检索 | qmd + FAISS + 混合检索 |
| **Phase 2** | 增强生成 | LLM API + 事实核查 |
| **Phase 3** | 完善生态 | API + 自动化 + 监控 |

**核心思想**：从 Demo 开始，先跑通流程，再逐步工程化。每一层的接口保持清晰，便于独立迭代。
